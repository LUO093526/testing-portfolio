## 二、核心知识清单

### 1. pytest fixture 机制

Fixture = 测试的"前置准备 + 后置清理"工具。

| 概念 | 说明 | 例子 |
|------|------|------|
| `yield` 前 | 前置操作（创建资源） | `api()` 启动测试服务器 |
| `yield` 后 | 后置操作（清理资源） | `api()` 关闭测试服务器 |
| `scope="module"` | 整个文件只执行一次 | 服务器只启动一次，所有用例共享 |
| fixture 返回 | 测试函数直接接收 | `sample_student()` 返回创建好的学生数据 |

**面试回答**："fixture 是 pytest 的依赖注入机制，在测试执行前后自动管理资源的创建和清理，避免重复代码。"

### 2. 测试标记分类（5种）

| 标记 | 数量 | 含义 | 使用场景 |
|------|------|------|---------|
| `@pytest.mark.smoke` 🏭 | 4条 | 冒烟 — 核心功能可用 | 每次push先跑 |
| `@pytest.mark.crud` 🔄 | 8条 | 增删改查完整流程 | 全量回归 |
| `@pytest.mark.exception` ⚠️ | 6条 | 异常输入处理 | 测试健壮性 |
| `@pytest.mark.boundary` 📏 | 4条 | 边界值测试 | 特殊场景 |
| `@pytest.mark.slow` 🐢 | 1条 | 耗时操作 | CI单独跑，日常跳过 |

**筛选命令：**
```bash
pytest -m smoke              # 只跑4条冒烟
pytest -m "not slow"         # 跳过慢测试
pytest -m "smoke or crud"   # 逻辑运算组合
pytest --html=reports/report.html --self-contained-html  # 生成报告
```

### 4. 等价类划分

**核心思想**：按"系统行为"分组，同一组行为相同，测一个代表即可。

| 场景 | 等价类 |
|------|--------|
| grade 筛选 | 不传→全部、存在的值→有结果、不存在→空列表 |
| name 输入 | 正常名→成功、缺字段→400、空串→201(不做校验) |

---

### 5. 边界值分析

**核心思想**：bug 爱蹲在边界上。

| 字段 | 边界点 | 发现 |
|------|--------|------|
| score | -1 / 0 / 1 / 100 / 101 | 负数-100也能存 ✅ |
| grade | "" / 负值 / 超大值 | -1年级也能存 ✅ |
| name | "" | 空名也能创建成功 ✅ |

## 三、关键发现：API 校验的"两档"

| 校验级别 | 检查 | 不检查 |
|---------|------|--------|
| ✅ 字段存在性 | name 字段在不在 JSON 里 | name 有没有意义 |
| ❌ 业务合法性 | — | 负数、空字符串、超长 |

**结论**：该 API 只做了字段级校验。真实项目中两种都要有，否则数据库进脏数据。
