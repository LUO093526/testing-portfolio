# 第1天（6月3日）— 读懂 API 测试代码

## 学到的东西

### 1. Fixture 机制
Fixture 是一个测试**前置**（准备数据、启动服务、创建资源）和**后置处理**（清理数据、关闭连接、销毁资源）的工具。
- `yield` 之前 = 前置操作（创建数据）
- `yield` 之后 = 后置操作（清理数据）
- `scope="module"` = 整个测试文件共享同一个 fixture，只执行一次

### 2. 测试标记分类
| 标记 | 用途 | 运行命令 |
|------|------|---------|
| `@pytest.mark.smoke` | 冒烟测试：只测核心流程，快速验证服务是否正常 | `pytest -m smoke` |
| `@pytest.mark.crud` | CRUD 完整测试：增删改查 + 异常场景 | `pytest -m crud` |
| `@pytest.mark.slow` | 慢速测试：日常跳过，CI 里跑 | `pytest -m "not slow"` |

### 3. 16 条用例分类
- **冒烟测试（4条）**：健康检查、列表返回、按姓名筛选、按年级筛选
- **CRUD 测试（9条）**：Create（正常+缺字段+空body）、Read（存在+不存在）、Update（存在+不存在）、Delete（存在+不存在）
- **数据验证（2条）**：默认值、特殊字符
- **并发测试（1条）**：连续创建删除，验证服务稳定性
