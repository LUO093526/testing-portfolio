# 第2天（6月4日）— 理解测试设计

## 学到的东西

### 1. 用例三分类：正常 / 异常 / 边界

| 类型 | 数量 | 含义 |
|------|------|------|
| 🟢 正常（Happy Path） | 8条 | 一切正确时，功能对了吗？ |
| 🔴 异常（Error Path） | 5条 | 输入错误时，报错对了吗？ |
| 🟡 边界（Boundary） | 3条 | 极端情况，扛得住吗？ |

### 2. 等价类

**核心思想**：按"系统行为"分组，行为一样的输入就是同一个等价类，测一个代表就够了。

例子：`grade` 参数有 3 个等价类：
- 不传/空值 → 不过滤，返回全部
- 传存在的值（2024/2025）→ 有结果
- 传不存在的值（2099/abc）→ 空列表

### 3. 边界值

**核心思想**：Bug 喜欢蹲在等价类之间的交界处。边界点 = 刚好等于、刚好小于、刚好大于。

例子：`score` 字段的边界在 -1/0/1/100/101，不是 50。

### 4. 等价类 vs 边界值的区别

| | 等价类 | 边界值 |
|------|--------|--------|
| 核心问题 | 有哪些不同的情况？ | 每种情况的临界点在哪？ |
| 怎么选数据 | 每类挑一个代表 | 挑临界点左右各一个 |

## 发现的缺失用例（明天新增）

1. score 负数（-1）— API 无校验，负数也能存
2. score 超满分（101/99999）— 超大数可能导致前端异常
3. grade 不存在（2099）— 等价类③，返回空列表的场景未覆盖
